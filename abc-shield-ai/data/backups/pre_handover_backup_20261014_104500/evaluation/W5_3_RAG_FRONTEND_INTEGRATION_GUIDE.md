# W5.3 — RAG → Frontend Integration Guide

---

## 1. Purpose

This document serves as the developer-facing integration guide for **Harshini (Frontend Lead)** and **Vishal (Backend Lead)**. It details how the client user interface and the product backend consume, deserialize, and render the structured output generated by Padma's AI/RAG engine.

The RAG engine is source-grounded, deterministic, and non-adjudicative. It flags factual evidence conditions and documented regulatory relationships without asserting legal determinations or automated compliance approvals.

---

## 2. RAG Endpoint

| Attribute | Specification |
| :--- | :--- |
| **HTTP Method** | `POST` |
| **Path** | `/api/v1/query` |
| **Content-Type** | `application/json` |
| **Response Model** | `StructuredAIResponse` |
| **Success Status** | `200 OK` (Note: Evidence gaps and conflict detections return HTTP 200 with structured status payload) |
| **Validation Error** | `422 Unprocessable Entity` (Empty query, whitespace-only, length > 2000, or unauthorized fields) |
| **Server Error** | `500 Internal Server Error` (Masked technical failure without stack traces) |

---

## 3. Request Example

Clients submit JSON payloads conforming to [`QueryRequest`](file:///d:/FInregTech%20Shipyard/abc-shield-ai/api/models/query.py). All fields except `query` are optional context attributes passed from Vishal's backend:

```json
{
  "id": "n1ggk9",
  "project_id": "PRJ-ABC-001",
  "query": "What regulatory requirements apply to our anti-bribery controls?",
  "requirement_ids": ["REQ-001", "REQ-002"],
  "advisor_advice_ids": ["ADV-UK-001"],
  "context": {
    "jurisdiction": "UK",
    "regulatory_area": "Anti-Bribery and Corruption"
  }
}
```

### Request Fields:
- `id` *(optional string)*: Correlation ID provided by backend. If supplied, echoed in `response.request_id`. If omitted, server generates `REQ-<uuid4>`.
- `query` *(required string, 1..2000 chars)*: Natural language regulatory inquiry.
- `project_id` *(optional string)*: Tenant / workspace isolation context.
- `requirement_ids` *(optional array[string])*: Upstream product requirement IDs associated with inquiry.
- `advisor_advice_ids` *(optional array[string])*: Upstream advisor advice note IDs.
- `context.jurisdiction` *(optional string)*: Vector retrieval filter (`"UK"` or `"EU"`).
- `context.regulatory_area` *(optional string)*: Workflow taxonomy hint.

## 9. Explanation of Citations

- **What they are:** Deterministic references tied to specific chunks that were present in the retrieved evidence set and synthesized by the grounded generator.
- **Key Fields:**
  - `chunk_id`: Granular chunk reference (e.g. `"RR-UK-01-C01"`).
  - `record_id`: Parent regulatory record reference (e.g. `"RR-UK-01"`).
  - `source_id`: Master source register identifier (e.g. `"UK-01"`).
  - `formatted_citation`: Human-readable label: `"[RR-UK-01-C01 | RR-UK-01 | Bribery Act 2010 | Section 1]"`.
  - `is_approved_for_rag`: Boolean approval status (`false` for candidate records).
- **Frontend Use:** Render inline citation pills or footnotes in the text. Clicking a pill highlights the corresponding item in the provenance drawer.

---

## 10. Explanation of Provenance

- **What it is:** Complete temporal, institutional, and legal lineage for every cited chunk, enabling audit compliance.
- **Key Fields:**
  - `regulation`: Official regulation name.
  - `section_article`: Specific legal section, article, or principle.
  - `official_source`: Canonical URL (e.g. `legislation.gov.uk` or EUR-Lex).
  - `effective_date`: Date the provision took legal effect.
  - `version_date`: Version timestamp of the text retrieved.
  - `jurisdiction`: `"UK"` or `"EU"`.
  - `similarity_score`: Cosine similarity score from dense vector retrieval.
- **Frontend Use:** Render in a slide-out "Evidence Provenance Drawer" with an outbound link to the official canonical URL.

---

## 11. Explanation of Conflict Findings

- **What they are:** Controlled pairings from the 11 registered relationships (`CO-001` through `CO-011`) where both sources are co-retrieved.
- **Taxonomy:**
  - `OVERLAP`: Complementary guidance or institutional relationships (10 pairs).
  - `VERSION_DIFFERENCE`: Amendment or temporal divergence (1 pair: `CO-010`).
  - `CONFLICT`: Direct substantive contradiction (0 pairs in canonical register).
- **Both-Source Requirement:** Surfaces if and only if BOTH sources exist in retrieved evidence. Single-source presence suppresses the card.
- **Strict Non-Adjudication:** The RAG system describes registered scope, authority, and version differences. It **NEVER** decides which regulation overrides the other.
- **Frontend Use:** Display dedicated warning cards displaying the topic, source comparison, and mandatory non-adjudication disclaimer.

---

## 12. Explanation of Evidence Gaps

- **What they are:** Structured explanations emitted when evidence is absent, insufficient, or out of scope.
- **Taxonomy (`gap.coverage_nature`):**
  - `CORPUS_COVERAGE_LIMITATION`: Provision or topic does not exist in the 15-record ABC Shield corpus.
  - `RETRIEVAL_LIMITATION`: Provision exists in corpus, but was not retrieved in top-$k$.
  - `OUT_OF_SCOPE`: Query falls outside UK/EU anti-bribery & AML scope.
  - `NEEDS_HUMAN_REVIEW`: Ambiguous provision boundaries requiring SME adjudication.
- **Safe Phrasing Invariant:** The system says: *"The requested provision is not represented in the current ABC Shield regulatory evidence corpus."* It **NEVER** says: *"The law does not contain this section."*

## 14. Human-Review Behavior

The boolean flag `metadata.requires_human_review` is set to `true` deterministically under any of these 4 conditions:
1. `len(response.conflicts) > 0`: Any documented regulatory overlap or amendment divergence is detected.
2. `gap.requires_human_review == true`: Provision ambiguity or unapproved evidence state occurs.
3. `status == "CONFLICTING_EVIDENCE"`: Contradictory regulatory evidence retrieved.
4. `status == "UNAPPROVED_EVIDENCE"`: Query attempts to treat candidate records as authoritative.

**Frontend Action:** Renders an amber status badge: *"Compliance SME Review Required"*.
